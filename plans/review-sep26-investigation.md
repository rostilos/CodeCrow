## Implemented provenance correction

The verifier ledger now joins an existing candidate's exact observed caller/guard witness with one already-visible changed-anchor record. Keeping or refining that candidate no longer requires the model to repeat the seed diff identifier. Dismissal and deduplication accept exact contrary-source witnesses independently of the original changed location. Missing or invented-only references remain unaccepted, unseen reads cannot supply provenance, and new findings still need an exact observed citation containing their active changed location. This addresses a protocol failure; it does not itself establish an F1 improvement.

## Implemented source-context correction

Discovery now loads an actual complete file scope when structural ownership is absent, malformed, or partial; the previous fallback supplied only diffs despite reporting a file scope. Deleted-line cases load the target snapshot, and unavailable target source cannot be replaced by proposed-tree graph coordinates. Exact enclosing definitions remain complete. Adjacent nonoverlapping definitions are no longer merged, so a later verifier case can reuse its complete definition without pulling in the next unrelated definition. Overlapping definitions still share a lossless source range. A whole added/deleted file already present in the diff is not copied into the prompt again.

Focused offline verification: 45 tests passed across `test_review_source_context.py` and `test_review_verification_state.py`. These exercise source selection and verdict provenance using local snapshots/scripted decisions. They do not measure live-model precision, recall, cost, or latency.

## Implemented protocol and navigation correction

The native adapter preserves tool-only messages as normal provider responses. Prose or malformed final content is returned to the case controller as a recoverable format problem, with the original response retained and explicit pending-work feedback. It no longer triggers the infrastructure-outage branch that preserves undecided discovery candidates. Every tool round identifies remaining work and rejected fields; repeated known evidence cannot continue an already-settled case, while new counterevidence can still revise a decision.

Cross-batch synthesis now uses separate calls for disconnected groups of contract scopes; each prompt keeps behavioral/contract/evidence facts without duplicating the separately supplied findings/questions. Valid sibling groups survive another group's failure. Candidate grouping uses the specific definition containing its anchor rather than the union of every definition touched by its hunk. The changed-file catalog uses paths, with complete diffs available by path or part ID. Literal grep returns every matched line and location without unrelated surrounding source, addressing the demonstrated BookingReference/Booking ambiguity. Exact matched lines are usable positive evidence even when other search paths are unavailable; missing or location-only results cannot establish a source claim or prove absence. Graph tool payloads replace storage IDs with case-local handles and factor repeated definitions. Nodes, edges, plugin attributes, coverage and continuations remain available; host-only snapshot attestations and scoring constants stay outside the model prompt. Host tenant/revision binding remains authoritative. Minimal-context retrieval resolves explicit unit handles through exact identity before falling back to symbol-name search, and prioritizes those requested roots over incidental changed-file anchors. Duplicate score/depth values are referenced through their node rather than repeated, while winning paths and occurrence-specific annotations remain. An offline projection of two graph responses reconstructed from exact Grafana source snapshots changed serialized sizes from 95,634 to 60,826 bytes and 113,742 to 73,198 bytes. These are response-size fixture checks, not replayed provider requests or measured paid-token/latency improvements.

The capture implementation now accepts an existing service-owned 0755 root without changing old artifacts. It rejects roots writable by other users or symlinks, and new tenant/run children remain 0700 with 0600 files. These fixes were not deployed during investigation and cannot retroactively recover the missing latest-run captures.

## Implemented scheduling correction

Independent verifier cases now share the existing service semaphore with discovery, cross-batch synthesis and final reconciliation across requests. They run with isolated state, tool handles and native conversations, sharing only the request-bound raw observation cache. Results are merged deterministically in planned case order; final reconciliation waits for all cases. An unexpected case setup/auxiliary failure preserves that case's discovery with a diagnostic while siblings continue. Cancellation propagates, cancels queued/running cases and releases capacity. Standalone callers without a supplied semaphore retain serial execution. No model stage, token budget, request quota or concurrency environment setting was added.

Five concurrency checks passed; the combined verifier/pipeline/case-context suite passed 86 tests. These test scheduling and isolation, not a measured latency improvement on the live corpus.
