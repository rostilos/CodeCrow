# Inference Orchestrator

The inference service consumes review jobs from Java and returns findings with an explicit completion state. Interactive ask, summarize, and QA documentation commands have separate handlers.

## Review path

Java supplies the acquired diff, provider revisions, project identity, staged target tree, and proposed-file overlay. An optional proposed-tree graph supplies structural relationships. The deterministic planner co-owns directly coupled changed contracts, retains complete hunks, and supplies exact companion changes at remaining boundaries; graph failure is reported while diff review continues.

Tool-free batch discovery uses medium reasoning effort and emits candidate findings and internal behavior, contract, and question summaries in the same response. Each finding explains its causal mechanism once in `reason`, with `sourceLocations` pointing to supporting ranges. Selective synthesis routes each connected group of remaining cross-batch scopes into source investigations; disconnected groups keep separate prompts and failure handling; discovery questions also reach verification directly when the graph is unavailable.

Each candidate or concrete source question starts as a separate verification case. Anchor-specific definitions and file/side fallbacks select complete evidence, not which claims must share a conversation. When multiple cases exist, one optional source-free planning call at low effort can merge repeated descriptions of one precise suspected failure and questions that directly prove or disprove it. A merged group names `failureMechanism` and `sharedResolution`; a common file, owner, configuration or API migration does not justify merging distinct defects. Missing, malformed or overlapping groups preserve affected original cases. Every case receives complete relevant hunks and available source. Independent cases share existing service capacity, reuse successful source observations, and merge in planned order before publication reconciliation.

Verification begins with an assessment phase exposing only `assessReviewWork`. Each supplied work ID gets an independent verdict from available evidence or `needs_evidence` naming a concrete missing causal fact. That outcome opens an evidence phase exposing the nine request-bound source tools plus the same assessment tool. Source calls include `workIds` and `missingFact`; every actual read attempt returns control to assessment with its observation or failure diagnostic. Further concrete facts can request further evidence phases, without a numeric read or turn allowance.

Native adapters receive only the current phase’s tools. Forced assessment selection or any-tool selection for evidence is requested only after checking adapter support; unsupported forced choice retains native automatic selection with a diagnostic. JSON-only adapters receive the selected assessment argument object or JSON tool calls for evidence. Provider failures do not trigger paid retries through another protocol.

Candidates and questions share one work-ID namespace. A usable source request keeps its named pending work provisional, including a same-response final verdict; independent outcomes settle normally. A read during the evidence phase needs no redundant assessment in the same response. Settled work requires explicit reassessment to reopen. Final confirmed explanations replace stale discovery prose unless an explicit issue explanation overrides them. New findings need active changed anchors. Unknown IDs and malformed records receive specific feedback. Provider failures retain the explicit partial fallback; formatting mistakes do not become outages.

Generated batch summaries guide routing and synthesis; they are not passed to the verifier as contract authority. The verifier receives unverified candidate claims, PR intent, project rules and exact source, and checks reachable before/after behavior, existing guards, actual configuration and library semantics when a claim depends on them.

After all cases, multiple distinct publication records trigger one source-free, tool-free semantic partition. It groups complete causal descriptions and locations, including verifier-created restatements, and selects existing representatives. It cannot rewrite, invent or revalidate issues. Invalid, missing or overlapping groups preserve affected records with diagnostics; provider failure preserves the records without a retry loop. Independently actionable defects may share an anchor. The same response may flag specific contradictory causal claims. The host preserves the complete affected duplicate/conflict component and source-checks only that component with retained exact proof and fresh bound tools. Inconclusive, uncertain, format-stalled or interrupted optional conflict checks preserve previously verified reports individually. Only supported refutations, confirmed replacements or grounded duplicate decisions change publication. No second global reconciliation call or universal extra pass runs.

Each step receives the current work ledger and canonical observed evidence. Complete hunks stay intact; identical overlapping source lines at the same path/side/location use references while preserving original bytes. Raw assistant prose, broken provider output and exploratory transcripts are not replayed. Graph handles remain case-local while successful raw observations are cached within the request. `grepReviewCode` requires literal or regex mode and returns complete matching lines; `findReviewFiles` resolves unknown paths by glob.

The controller tracks source facts, outcomes and canonical executed tool arguments. Distinct concrete source queries may explore new leads even when they return no matches, without a negative-query count limit. Rewording the missing-fact explanation for the same source call does not advance work. Repeated unchanged work gets an assessment opportunity and correction feedback before unresolved termination; a concrete missing-fact disposition can still follow another source route, including graph-to-local fallback.

A rejected issue remains attached as `pendingIssue` with `issueCorrections` that distinguish missing report fields from invalid anchors or unavailable evidence. A title-only patch preserves the existing location and reusable citations; current assessment reasons and citations supersede old ones, with explicit issue fields taking precedence. A missing title does not prompt another source search and is never invented. The model may explicitly withdraw a proposed issue with `issue: null` and a reason. There is no token/read/turn quota. Architecture checks do not establish cost or quality improvements.

A finding must use a changed-code anchor and explain a source-supported failure. Missing or mistyped hunk IDs resolve through an unambiguous exact active file/line; they never permit line guessing or expansion beyond an incremental delta. Inference returns `complete`, `partial`, or `error`. Unresolved discovery, verification or publication-grouping scopes remain explicit. Normal unsupported hypotheses remain unpublished with partial diagnostics. Verifier infrastructure failure preserves undecided discovery candidates as an explicit partial fallback; malformed final text instead receives format-repair feedback and does not publish undecided hypotheses as an outage fallback; graph failure alone does not force partial status when the core review can finish. Java persists partial outcomes as `PARTIAL`, excludes them from completed-result caching, and refreshes the same durable record on retry. Java owns provider publication.

## Runtime and checks

`RAG_API_URL` configures graph-service access and `REDIS_URL` configures the internal queue. Java supplies model credentials and routing settings per request. Graph receipts and local source roots are scoped to the project and pinned review revision.

Run the focused Python review tests with the service dependencies installed. Benchmarks are a separate operation and require the same fixed corpus, model/provider settings, judge, and token/cost accounting for both implementations. Architecture and unit tests establish contracts, not precision, recall, F1, speed, or cost changes.


## Exact provider capture

For a future run, opt in with `REVIEW_QUALITY_CAPTURE_ENABLED=true` and optionally restrict `REVIEW_QUALITY_CAPTURE_PROJECT_IDS` to comma-separated project IDs. An empty filter captures all review projects. Compose persists artifacts under `/app/logs/review-quality-captures`; standalone inference can choose `REVIEW_QUALITY_CAPTURE_OUTPUT_DIR`.

The capture records actual SDK HTTP request/response bodies, including native tools, reasoning/routing options, complete source and usage. Each SDK attempt has private request/response files and start/completion manifests correlating the project, review run, durable queue job when present, stage, batch, turn, call and provider generation. Request auth headers, URL queries and the credential DTO are not serialized. New tenant/run directories use `0700`, files use `0600`, and tenants/runs have separate paths. Existing service-owned `0755` capture roots are accepted without modifying old artifacts; roots writable by another user remain unavailable. Source and returned text remain intact. Capture errors log a diagnostic without failing review; there is no automatic truncation or retention limit. Streams are copied as consumed, and manifests describe response compression/interruption.

Public operator instructions and architecture are maintained in the sibling documentation repository at `codecrow-static/src/pages/Docs/en/developer/configuration.mdx` and `review-orchestration.mdx`. `tests/provider_capture_protocol_checks.py` compares capture bytes against mocked real-SDK transports without network/model calls. These protocol tests do not establish review quality or paid cost.
